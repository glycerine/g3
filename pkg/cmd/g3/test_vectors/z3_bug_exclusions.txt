# Vectors excluded from z3 trace/output identity testing because g3
# deliberately fixes a z3 4.7.1 bug that they expose. Details, reproductions
# and code locations: TODO.md, section "z3 4.7.1 bugs fixed in g3".
#
# OPB max: objectives: opb::parse tries parse_token("min:") before
# parse_token("max:"), and parse_token consumes the matching prefix "m", so
# z3 4.7.1 reads "max:" as "ax:" and exits with (error line 1 "unexpected
# char: a" expected "x") (z3 bug: src/opt/opt_parse.cpp:74-82 parse_token,
# :283-301 opb::parse; still present upstream). g3 parses max: objectives
# (pkg/opt/opb_parse.go ParseOPB; AUDIT.md opt_02-F4). Not an SMT-LIB
# vector: the case opb-max-objective in
# pkg/cmd/g3/optimization_frontend_test.go locks g3's answer.
#
# Interaction-log replay of Z3_mk_pble/pbge/pbeq: the generated
# log_Z3_mk_pble writes the int coefficients with U and Au, while
# exec_Z3_mk_pble reads them with get_int_array, so z3 4.7.1 replays no log
# of these calls ("[z3 exception]: expecting int_array at position 3 but got
# uint_array") (z3 bug: scripts/update_api.py INT in-array logging; fixed
# upstream in fed977b49, "fix #1782", which logs I/Ai and replays 'i'
# arrays). g3 replays both formats (pkg/api/z3_replayer_parse.go,
# z3_generated_pseudo_boolean_commands.go; AUDIT.md api_03-F3). Not an
# SMT-LIB vector: TestZ3LogFrontendReplaysPseudoBooleanCoefficients in
# pkg/cmd/g3/z3_log_frontend_test.go locks both.
#
# qe's datalog (finite-domain) plugin, in the "other value" branch of a
# large domain, substitutes true for the equality atoms that occur
# negatively, against its own assign_large_domain, which asserts their
# negation; exists x. x != c (domain size 4) becomes false (z3 bug:
# src/qe/qe_dl_plugin.cpp subst_large_domain; still present upstream; the
# datatype plugin substitutes false). g3 substitutes false
# (pkg/qe/datalog_branch.go Substitute; AUDIT.md qe_01-F4). SMT-LIB 2 has no
# finite-domain sorts, so there is no vector; see
# TestDatalogPluginOtherBranchPreservesNegativeEqualitySemantics in
# pkg/qe/datalog_branch_test.go.
#
# qe's datalog (finite-domain) plugin picks the large-domain mode when the
# domain size equals the number of equality atoms (is_small_domain tests
# domain_size < #atoms). Its "other value" branch then assumes a value that
# differs from every atom, which need not exist, so exists x:S(2).
# x != y and x != z becomes true instead of (= y z) (z3 bug:
# src/qe/qe_dl_plugin.cpp is_small_domain; still present upstream). g3
# enumerates the domain when domain_size <= #atoms
# (pkg/qe/datalog_atoms.go datalogQEBranchCount; AUDIT.md qe_01-F4). No
# vector (SMT-LIB 2 has no finite-domain sorts); see
# TestDatalogQEDomainBoundaryBruteForce and
# TestDatalogQEDomainBoundaryNumerals in
# pkg/qe/quantifier_tactic_datalog_search_test.go.
#
# sieve_relation_plugin::mk_filter_by_negation_fn computes its "column is
# inner" flags as !is_inner_col, so an equality between two inner columns
# is dropped (the inner relations are subtracted on zero columns, emptying
# the target whenever the negated relation is nonempty), an equality on a
# full negative column becomes the identity, and the inner column is looked
# up by the equality's index instead of its column (z3 bug:
# src/muz/rel/dl_sieve_relation.cpp mk_filter_by_negation_fn; still
# present upstream). g3 joins inner columns, skips full negative columns
# and keeps a full target column as the identity
# (pkg/muz/rel/udoc_sieve_negation.go, sieve_operations.go FilterByNegation,
# sieve_relation_table_negation.go; AUDIT.md muz_rel_06-F5). Sieve
# relations come only from datalog.explanations_on_relation_level, which
# rel_context applies only to API queries (query(expr)), not to the SMT-LIB
# (query p) command, so there is no vector; see
# TestUDocSieveNegationColumnClassification and
# TestSieveNegationFullNegativeColumnSubtractsAll in
# pkg/muz/rel/udoc_sieve_negation_test.go.
#
