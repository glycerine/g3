# Scale transform source audit

Scope: `src/muz/transforms/dl_mk_scale.cpp` and `.h`, both marked ported before this audit. This is a source and consumer audit, not a whole-transform completion claim. The unit remains **partial**: the transformation and model-conversion paths exist, but the live consumer and ownership evidence below does not justify a whole-unit ported status.

## Consumers

`dl_transforms.cpp:42-101` registers `mk_scale` at priority 36030 in the default transformer; `operator()` itself returns null unless `context::scale()` is enabled (`fixedpoint_params.pyg` defaults `xform.scale` to false). Actual callers of that default transformation are PDR, Spacer, BMC, CLP, the Horn tactic, and Duality's quantified-array path (`pdr_dl_interface.cpp:103`, `spacer_dl_interface.cpp:110,203`, `dl_bmc_engine.cpp:1457`, `clp_context.cpp:70`, `horn_tactic.cpp:329`, `duality_dl_interface.cpp:168`). The similarly named empty context member in `dl_context.cpp:736` is not that free function. The source model converter is installed only when the context requests a model converter; it is a live result-conversion obligation, not dead code. No other source instantiations of `mk_scale` were found.

Go's shared `preprocessHornRulesWithStages` reads the same default-false option, registers `ScalePlugin` at 36030, captures its predicate map and adds a scale model-conversion ledger (`pkg/muz/fp/spacer_engine.go:167,203,416,505`). It is reached by the Go PDR, Spacer, BMC, CLP, Horn tactic and Duality preprocessing callers. Model reconstruction is implemented in `pkg/muz/fp/spacer_scale_results.go` and consumed through the common conversion sequence in `spacer_slice_results.go`; PDR retains the same ledger in `pdr_engine.go`. Consumer presence is not evidence that every query, proof or model path is equivalent.

## Source-to-Go mapping and evidence

- Source constructor, priority and disabled no-op: `ScalePlugin` owns manager, rule manager and priority; its caller conditionally registers it. Direct `Transform` always transforms, so the no-op is a pipeline responsibility. Default priority 33039 is a C++ constructor default; the live registration supplies 36030, as does Go.
- Source `operator()` loops through rules, clears per-rule caches, obtains variable count, rewrites positive and negative uninterpreted tails, then interpreted tails and head, appends equality constraints and positive sigma, creates all-false negation flags, preserves the rule symbol and propagates output heads. `scale.go:231` performs these steps. All-false flags reproduce the source, including for originally negated tails; this audit does not assert that scaling negated rules is logically sound. `InheritPredicate` also records origin and metadata for the Go consumer.
- Source `mk_pred` extends each signature with Real sigma, leaves zero, substitutes sigma for one, introduces a fresh Real variable and equality for other numeral arguments, appends sigma and registers each predicate. `scale.go:56` implements these branches and caches old-to-new declarations. `TestScaleAddsHomogeneousPredicateArgumentAndGuards` checks zero/one, arity and guard count; `TestScaleReusedDeclarationInheritsCurrentOutputs` checks reuse, output metadata and origin; `TestRuleName...` auxiliary-symbol coverage exercises the source rule symbol through this transform.
- Source `linearize` memoizes applications; it descends through basic-family operators and arithmetic add/subtract/comparisons, multiplies isolated numerals by sigma, and leaves other applications and non-applications unchanged. `scale.go:150` follows that structure. The scale-specific tests above do not directly verify the full interpreted expression tree, cache sharing, other arithmetic operators, multiple equality indices or multiple rules.
- Source converter maps each new declaration back to its old declaration, substitutes sigma = 1 into total, entry-free function interpretations, retains unscaled interpretations and replaces the model. `expandSpacerScaledFunction` implements the substitution, removes derived declarations and registers originals; the surrounding conversion pipeline carries other model entries. `TestSpacerScaleReconstructsOriginalPredicateModel` exercises direct unary reconstruction and the nullary adaptation below, not a complete public query/model lifecycle. Source's `translate` is explicitly unreachable and needs no generic translation adapter.
- The C++ destructor relies on reference-owned trails and its converter's declaration trail. Go rule-local pins are released by `scaleRuleState.release`, replacement rules and source rule handles are closed, and the transformer closes the plugin. The persistent declaration map is borrowed and its `FreshPredicates` result is copied before transformer close. This is a mapping of intended ownership, not an exceptional-cleanup proof.

## Open obligations

1. Add source-derived end-to-end tests with `xform.scale` enabled through the actual default preprocessing/query consumers, including a model evaluated against original rules and a query, composition with other conversions, and output/query mapping. Check PDR, Spacer, BMC, CLP, Horn and the conditional Duality path individually; shared construction alone does not establish their result contracts. Verify disabled behavior at the public parameter boundary.
2. Cover source branches for nested basic/arithmetic constraints, untouched multiplication and other operators, zero/one/non-unit numerals across tails and head, multiple variables and rules, output ordering, rule symbols, and source's negation handling. Check source numerical sort restrictions and error behavior for mixed/non-Real inputs instead of assuming the algorithm applies universally.
3. Audit proof/answer/trace behavior on enabled scaling. The source unit installs no proof converter, but engine-specific contracts still need to be established against the actual source consumers; do not infer original-rule proof preservation from the predicate map.
4. Audit converter absent interpretations, unrelated declarations, partial/entry-bearing interpretations and conversion order. The nullary case is a confirmed source discrepancy: `mk_pred` increases arity, so the converter's test of the **new** arity enters the function branch for an original nullary predicate. It registers a zero-arity function interpretation, violating the `d->get_arity() > 0` assertion in `src/model/model_core.cpp:67`; in unchecked builds the function-map entry is not found by the constant lookup used by `model_evaluator.cpp:126`. Go instead substitutes sigma = 1 and registers an evaluable constant. The direct regression checks the resulting constant and removal of the scaled declaration. This intentional Go adaptation preserves functionality but is not source-equivalent; public-query reachability remains unverified. Source asserts the general function case has no entries and is total; Go returns explicit errors for entries or missing fallback.
5. Exercise allocation, cancellation and independent cleanup failures. In particular `scaleRuleState.release` iterates local pins and returns joined errors without retaining that state for retry; `Transform` also defers a result `Close` without retaining a refused owner. Predicate registration and `oldToNew` publication happen during construction, before a complete result. Determine actual failure semantics and repair retry/ownership or transactional publication where required. The focused success tests do not cover these paths.

Focused verification (2026-11-03): `go test ./muz/transforms -run 'TestScale|TestRuleName' -count=1` and `go test ./muz/fp -run TestSpacerScaleReconstructsOriginalPredicateModel -count=1` both pass from `pkg`. These checks establish the stated examples only; no full native suite was run for this audit.
