# Spacer matrix source audit

Scope: `src/muz/spacer/spacer_matrix.h` and `spacer_matrix.cpp`, previously marked ported. This is a unit audit, not a claim that the Farkas learner, interpolation solver, or Spacer engine is complete.

The only production inclusion and consumer is `spacer_unsat_core_plugin.cpp`: optimized Farkas `finalize` builds a matrix from nonempty linear combinations, eliminates it, and reads nonzero coefficients into core lemmas. `spacer_itp_solver.cpp` selects that plugin when new-core and optimized-Farkas modes are enabled. Its literal `if (true)` makes the alternative bounded plugin unreachable; that alternative alone calls `print_matrix`, `normalize`, and `num_rows`. No other matrix consumers were found in `src`. The Go path runs through `ItpSolver`'s `ItpCoreNewOptimized` selection and `UnsatCoreOptimizedFarkasPlugin.Finalize` in `pkg/muz/spacer/itp_solver.go` and `unsat_core_plugin_farkas_optimized.go`. It constructs the basis in encounter order, sets coefficients, performs elimination, and reads the resulting rows. `TestUnsatCoreFarkasPluginClosesArithmeticMixedStep` exercises an optimized proof consumer; its one-lemma/non-null assertion does not independently verify every coefficient or multirow core. Full interpolation and proof correctness remain separate obligations.

| Source operation | Go correspondence and evidence |
| --- | --- |
| Constructor, row/column dimensions and zero initialization | `newSpacerMatrix`, `numRows`, `numCols` in `matrix.go`; optimized consumer supplies combination and basis counts. |
| `get` and `set`, bounds assertions | `get` and `set` return domain errors for invalid indices (and nil input); Go copies on both boundaries, whereas C++ `get` returns a const reference and `set` copies. `TestSpacerMatrixOwnershipAndSignedPivot` verifies independence. The consumer neither depends on reference identity nor mutates through a returned value. |
| Elimination: signed maximum, skip zero, row assignment, pivot division, elimination from row 1, returned pivot count | `gaussianElimination` preserves these orders, including source's duplicated row on a pivot change and failure to revisit row zero. `TestSpacerMatrixNormalizeAndSourceEliminationOrder` covers row duplication and subtraction order; `TestSpacerMatrixOwnershipAndSignedPivot` covers zero beating a negative candidate. |
| Normalization by LCM of all denominators | `normalize` and `lcmBigInt`, with fractional denominators checked in `TestSpacerMatrixNormalizeAndSourceEliminationOrder`. The only source call is unreachable bounded Farkas. |
| `print_matrix` verbose output | No Go implementation; its sole source caller is the unreachable bounded branch described above. |

C++ locals and matrix cells own rationals; the Go slice owns `big.Rat` values, with independent copies from `get` and `set`. No AST, proof, model, or external references are owned by this unit. Empty dimensions return zero from Go elimination. C++ short-circuits zero rows but asserts nonempty at verbosity >= 1; the live optimized consumer first rejects zero combinations and debug-asserts each combination is nonempty, so that diagnostic difference is outside its valid input. A zero-column matrix with positive rows terminates in both implementations. Go's bounds errors and nil handling are defensive adaptations outside the source preconditions.

`TestOptimizedFarkasMultirowCoreSourceOracle` now seeds two three-term combinations and checks the source-derived eliminated consequences `x+y<=0` and `y+z<=0`. This exposed and fixed an SMT Farkas operator-family collision between arithmetic `<=` and basic equality. The test seeds combinations directly; it does not validate proof marking or the complete interpolation proof. No live matrix implementation gap was found in this audit.
