# Horn tactic factory audit

Scope: `src/muz/fp/horn_tactic.h`, its two actual factory definitions and the named Go command/API consumers. This is not a whole audit of `horn_tactic.cpp`, its transformation pipeline, proof/model conversion, or exceptional cleanup. The manifest currently marks the header ported but its `mk_horn_simplify_tactic` method `reference_only`; that method classification is stale. Both factory entry points and registrations have live implementations. The method should be recorded as implemented/ported at factory scope, without promoting the separately partial implementation unit.

| Source evidence | Go evidence and scope |
| --- | --- |
| `horn_tactic.h:19–35` has only an include guard, `tactic.h`, two declarations with default empty `params_ref`, and `ADD_TACTIC` registrations: `horn` and `horn-simplify`. The parameter deletion error path and broader independently failing cleanup continuation are not established by this factory audit. |

Evidence for the named simplify consumer: `api/api_tactic_horn_alias_test.go` `TestAPIHornSimplifyNamedFactory` constructs and applies the API name and closes its tactic, result and subgoal. `fp/horn_tactic_simplify_test.go` checks transformed goals and inlining; `fp/horn_simplify_pipeline_test.go` checks the default pipeline and optional slicing. The latter documents a source slice-order defect, so it is not a blanket soundness claim. Verification mode has finite default-proof and infinite PDR selection/model tests in `fp/horn_tactic_datalog_proof_test.go` and `fp/horn_tactic_infinite_test.go`. Parameter, translation, statistics and progress tests exercise the common tactic interface; the lifecycle fixture covers both constructors, but does not establish every allocation or native cleanup failure path.

The source-registered factory is therefore not dead or reference-only. This conclusion covers factory modes, registration and the observed ownership adaptation only. The broader `horn_tactic.cpp` is partial: source verification uses its sole query directly and creates a synthetic query and model filter only for zero or multiple queries, while Go currently always creates a synthetic verification query. Reachable proof-enabled results now publish an independently owned proof converter; the broader query, model, transformation and failure-path obligations remain open.
